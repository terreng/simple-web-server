# Building

> **Heads-up:** this app targets **Windows and macOS only** (no Linux). The
> repository was developed on Linux, where the Rust core and the shared C++
> supervisor are fully build- and run-verified. The React Native app and the
> per-platform native modules must be compiled on their respective OSes with the
> official toolchains — they cannot be built on Linux.

## 0. Layout recap

```
app/
  src/                     React Native UI (TypeScript) — shared by both platforms
  native-common/           SwsSupervisor — portable C++ core (both platforms)
  rust-server/             Vendored Rust core + sws-ffi (C ABI)
  macos/SimpleWebServer/   macOS native module (ObjC++) — drop into the RN-macOS shell
  windows/ServerManager/   Windows native module (C++/WinRT) — drop into the RNW shell
  docs/
```

`macos/` and `windows/` here hold **just our native sources**. The actual app
shells (Xcode project / VS solution) are generated by the official init tools,
then our sources are added to them (steps below).

## 1. Build the Rust core (all platforms)

```sh
cd app/rust-server
cargo build -p sws-ffi --release
```

Outputs in `app/rust-server/target/release/`:

- `libsws_ffi.a` (macOS/Linux static) / `sws_ffi.lib` (Windows)
- `libsws_ffi.{so,dylib}` / `sws_ffi.dll`

Requires a C compiler, `perl`, and `make` (for `openssl` with the `vendored`
feature). The C header the native code includes is
`app/rust-server/ffi/include/sws_ffi.h`.

For a universal macOS build:

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cargo build -p sws-ffi --release --target aarch64-apple-darwin
cargo build -p sws-ffi --release --target x86_64-apple-darwin
lipo -create -output libsws_ffi.a \
  target/aarch64-apple-darwin/release/libsws_ffi.a \
  target/x86_64-apple-darwin/release/libsws_ffi.a
```

### Verifying the core without a GUI (done on Linux)

```sh
# builds libsws_ffi, then a tiny C program that starts a server and curls it
cc smoke.c -Iapp/rust-server/ffi/include -Lapp/rust-server/target/release \
   -lsws_ffi -lpthread -ldl -lm -o smoke && ./smoke ./webroot
```

The supervisor has an equivalent C++ harness; both live in the commit history /
`docs`. This proves the create/start/terminate/reconcile + port-in-use +
cert-generation paths independent of any GUI.

## 2. Install JS deps

```sh
cd app
npm install
npm run tsc     # typecheck
```

`react-native`, `react-native-windows`, and `react-native-macos` are pinned to
the **same 0.77.x** line — keep them aligned when upgrading.

## 3. macOS

1. Generate the macOS shell (first time only):
   ```sh
   npx react-native-macos-init
   ```
2. Add our sources to the macOS app target in Xcode:
   - `app/macos/SimpleWebServer/*.{h,mm}`
   - `app/native-common/SwsSupervisor.{hpp,cpp}`
3. Build settings on the app target:
   - **Header Search Paths:** `$(SRCROOT)/../native-common` and
     `$(SRCROOT)/../rust-server/ffi/include`
   - **Other Linker Flags:** `-lsws_ffi`; **Library Search Paths:** the
     `target/release` dir (or your universal output). Also link `libresolv`
     and the system frameworks already present.
   - Add a **Run Script** phase before "Compile Sources" that runs
     `npm run rust:build` (or the universal variant) so the static lib is fresh.
4. Merge `AppDelegate.reference.mm` into the generated `AppDelegate` (starts the
   core at launch, background/dock-hide, menu-bar restore).
5. Add the menu-bar template image `menuBarIconTemplate` to the asset catalog
   (reuse `images/menuBarIconTemplate*.png` from the Electron app).
6. Run: `npm run macos`.

### Mac App Store build

- Enable **App Sandbox**. Entitlements:
  - `com.apple.security.files.user-selected.read-write`
  - `com.apple.security.files.bookmarks.app-scope`
  - `com.apple.security.network.server` (serve over the network)
  - `com.apple.security.network.client` (update check / open links)
- `SWSBookmarks` auto-detects the sandbox (`APP_SANDBOX_CONTAINER_ID`) and the
  core wires bookmark acquire/release around each server. **This can only be
  verified in a signed MAS build** — stale-bookmark handling surfaces in the UI
  as "Please re-select the folder."

## 4. Windows

1. Generate the Windows shell (first time only):
   ```sh
   npx react-native-windows-init --overwrite
   ```
2. Add our sources to the app `.vcxproj`:
   - `app/windows/ServerManager/*.{h,cpp}`
   - `app/native-common/SwsSupervisor.{hpp,cpp}`
   - Ensure `AppCore.cpp`/`ConfigStore.cpp` see a `pch.h` with the includes in
     `pch.reference.h`.
3. Project settings:
   - **Additional Include Directories:** `..\native-common` and
     `..\rust-server\ffi\include`
   - **Additional Dependencies:** `sws_ffi.lib;iphlpapi.lib;ws2_32.lib;…`
   - **Library Directories:** the Rust `target\release` dir.
   - Add a pre-build event running `npm run rust:build`.
4. Register the module in your `ReactPackageProvider::CreatePackage`:
   ```cpp
   packageBuilder.AddModule(L"ServerManager",
       winrt::Microsoft::ReactNative::MakeModuleProvider<
           winrt::SimpleWebServer::ServerManager>());
   ```
5. Wire `TrayBackground.reference.cpp` into the main window (subclass its HWND,
   call `SwsInitTrayBackground(hwnd)` after creation). This gives hide-on-close
   background + optional tray.
6. Run: `npm run windows`.

## 5. Icons / assets

Reuse the existing brand assets from the repo root (`images/`): app icons, and
the macOS `menuBarIconTemplate*.png`. `src/assets/logo.png` is already copied in.

## Known limitations of this deliverable

- Native builds are **not** CI-verified here (Linux dev box). Expect to iterate
  on Xcode/VS project settings and the RN 0.77 template specifics.
- Update-check (`update` event) is scaffolded in the JS/native contract but the
  HTTP fetch against `simplewebserver.org/versions/*` is not re-implemented in
  the native core yet; wire it into the app core if you want the banner live.
- Drag-and-drop to set a folder is intentionally omitted (as in Electron, it is
  unsolved for MAS bookmarks).
